# Mumble Web Discord

Веб-клиент Mumble с интерфейсом в стиле Discord: голосовые каналы и чат
прямо в браузере, без установки настольного клиента.

Это форк [johni0702/mumble-web](https://github.com/johni0702/mumble-web).
Оригинальный браузерный клиент и реализация интеграции с Mumble — работа
авторов исходного проекта. Этот репозиторий развивает его интерфейс,
аудиотракт и способ развёртывания.

## Что доработано в этом форке

- **Интерфейс в стиле Discord:** тёмная тема по умолчанию, боковые панели
  серверов и каналов, статус голосового подключения, чат и адаптивные диалоги.
  Исходные светлая и тёмная темы сохранены: `?theme=light` и `?theme=dark`.
- **Простое подключение:** посетитель вводит имя и пароль Mumble. Адрес сайта
  определяется автоматически, сервер назначения задаётся при развёртывании.
- **Аудио:** захват и воспроизведение переведены на AudioWorklet, используется
  общий AudioContext, исправлено хранение буфера начала речи. Добавлен буфер
  воспроизведения для сглаживания неравномерного прихода пакетов. Эти изменения
  направлены на устранение треска и разрывов при нагрузке на страницу.
- **Сборка:** Node.js 22, Webpack 5 и Dart Sass вместо старого `node-sass`;
  добавлены тесты аудиобуферов и совместимости Mumble-протокола.
- **Безопасность:** обновлены зависимости, HTML-санитизация и protobuf;
  удалён диагностический вывод аргументов подключения с паролем. Контейнер
  работает без root, с ограничениями ресурсов и файловой системой только
  для чтения. Подробнее — [SECURITY.md](SECURITY.md).

## Как это работает

```text
Браузер → HTTPS/WSS-прокси → контейнер Mumble Web + websockify → Mumble-сервер
```

Контейнер отдаёт веб-интерфейс и передаёт WebSocket-соединение на один
существующий Mumble-сервер через TLS. Сам Mumble-сервер в этот проект
не входит. В Docker-конфигурации голос передаётся через WebSocket;
WebRTC по умолчанию отключён. Для отдельной установки с WebRTC понадобится
[mumble-web-proxy](https://github.com/johni0702/mumble-web-proxy)
и соответствующая настройка клиента.

## Развёртывание на сервере

Понадобятся Docker с Compose, работающий Mumble-сервер и домен,
направленный на сервер с HTTPS-прокси. Ниже пример с Caddy; можно использовать
другой прокси с поддержкой WebSocket. Для выпуска сертификата Caddy должны
быть доступны порты 80 и 443. Браузеру нужен HTTPS для доступа к микрофону.

### 1. Скачать проект и задать сервер Mumble

```sh
git clone https://github.com/Lvov-SA/mumble-web-discord.git
cd mumble-web-discord
cp .env.example .env
```

Отредактируй `.env`:

```dotenv
MUMBLE_SERVER=mumble.example.com:64738
CADDY_NETWORK=caddy-proxy
WEB_SIMPLE_LOGIN=true
WEB_ADDRESS=
WEB_PORT=
```

`MUMBLE_SERVER` — адрес **самого Mumble**, доступный из контейнера.
Если Mumble запущен на том же хосте, можно использовать
`host.docker.internal:64738`: этот адрес уже предусмотрен в Compose.
Mumble должен слушать адрес, доступный контейнеру; хостовый `127.0.0.1`
из контейнера недоступен. Если Mumble работает в другом контейнере,
обеспечь общую сеть и используй его сетевое имя.

`.env` исключён из Git и контекста сборки. Пароль сервера сюда записывать
не нужно: его вводит пользователь в браузере.

### 2. Подключить HTTPS-прокси

Создай общую Docker-сеть, если её ещё нет:

```sh
docker network inspect caddy-proxy >/dev/null 2>&1 || docker network create caddy-proxy
```

Если Caddy уже работает в Docker, подключи его к этой внешней сети
и добавь в его Caddyfile блок, заменив домен на свой:

```caddy
voice.example.com {
    encode zstd gzip
    header {
        X-Content-Type-Options nosniff
        X-Frame-Options DENY
        Referrer-Policy no-referrer
        Permissions-Policy "camera=(), geolocation=(), microphone=(self)"
    }
    reverse_proxy mumble-web:8080
}
```

Если прокси ещё нет, его можно запустить отдельным Compose-проектом.
Сохрани блок выше как `Caddyfile` рядом с таким `compose.yaml`:

```yaml
services:
  caddy:
    image: caddy:2-alpine
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    networks:
      - caddy-proxy

networks:
  caddy-proxy:
    external: true

volumes:
  caddy_data:
  caddy_config:
```

Запусти этот отдельный проект командой `docker compose up -d`.
Если используешь существующий прокси, сохрани его остальные настройки;
после добавления сети пересоздай контейнер, после изменения Caddyfile
примени конфигурацию. Основной Compose клиента не публикует порт 8080
на хосте: прокси обращается к нему по общей Docker-сети.

### 3. Запустить клиент

Из каталога **mumble-web-discord**:

```sh
docker compose config --quiet
docker compose up -d --build --wait
docker compose logs --tail=50 mumble-web
```

Открой `https://voice.example.com`, разреши доступ к микрофону,
введи имя и пароль Mumble. Авторизация и права доступа определяются
на самом Mumble-сервере.

Контейнер ограничен 512 МиБ памяти, 2 CPU и 128 процессами. При большой
нагрузке подбери лимиты в `compose.yaml` под число подключений.

### Настройки подключения

| Переменная | Назначение |
| --- | --- |
| `MUMBLE_SERVER` | Обязательный адрес Mumble-сервера в формате `host:port`. |
| `CADDY_NETWORK` | Имя внешней Docker-сети прокси; по умолчанию `caddy-proxy`. |
| `WEB_SIMPLE_LOGIN` | `true` — имя и пароль, фиксированные параметры подключения; `false` — расширенная форма. |
| `WEB_ADDRESS` | Публичный адрес сайта; пустое значение берёт адрес из браузера. |
| `WEB_PORT` | Публичный порт сайта; пустое значение берёт порт из браузера, обычно 443. |

`WEB_ADDRESS` и `WEB_PORT` относятся к **сайту**, а не к внутреннему
Mumble-серверу. Переменные `WEB_*` публичны: из них при старте создаётся
`config.local.js`. Изменения `.env` применяются через `docker compose up -d --wait`.
В простом режиме параметры адреса и транспорта из URL игнорируются.

### Обновление

```sh
git pull
docker compose build --pull --no-cache
docker compose up -d --wait
```

Перед обновлением сохрани свои настройки `.env` и прокси. Перезапуск
клиента прервёт текущие веб-подключения. Пересборка с `--pull --no-cache`
также обновляет базовые образы и устанавливаемые системные пакеты.

## Локальная сборка и проверки

Нужен Node.js 22:

```sh
npm ci
npm test
npm audit
npm run build
```

`npm ci` уже собирает проект через `prepare`. Отдельный `npm run build`
нужен после изменений. Результат находится в `dist`.
Для работы голоса одной раздачи статики недостаточно: нужен WebSocket-прокси
к Mumble и HTTPS. Локальный `localhost` браузеры допускают для доступа
к микрофону без HTTPS.

Общие настройки описаны в [app/config.js](app/config.js). При самостоятельной
раздаче `dist` переопределяй их в `dist/config.local.js`; в Docker этот файл
генерируется из окружения при каждом старте. Для изменения кода полезен
`npm run watch`.
